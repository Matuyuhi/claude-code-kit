# web-ui-guidelines — web UI 実装の既定

## 最初に repo のスタックを確認する

スタイリング方式（CSS Modules / styled-components / Emotion / Tailwind 等）、デザイントークンの置き場所、既存の共通コンポーネント、ディレクトリ構成は repo ごとに違う。書き始める前に既存コンポーネントを数個読み、その repo のやり方に合わせる。この skill の既定と repo の既存パターンが食い違う場合は repo 側を優先し、食い違いがあったことを報告する。

アクセシビリティ（WCAG・ARIA・コントラスト比・キーボード操作）は design-implementation-guide を参照する。

## 表示と操作の既定（指示が無くてもこう作る）

- 閲覧専用の表示に `readOnly` / `disabled` の入力欄を使わない。表示用と編集用で DOM を分け、閲覧時は素のテキストで出す（編集できそうに見えるのにできない、という中途半端な見え方になるため）
- リストの各行の補助アクション（詳細リンク等）は常時表示にしない。hover / focus 時だけ出す。アイコンは `>`（chevron）のような素朴なものにする
- 詳細ビュー・モーダルを開いたら URL に反映する（`history.replaceState` で `?id=N` 等）。リンクをそのまま共有できる状態が期待値
- フィルタ・タブなど、共有や再訪で同じ状態を再現したいものも URL のクエリに持つ
- コントロール（スイッチ・チェックボックス等）を足すときは、置いただけで出さない。①共通部品が label を画面に出すか確認し、出さない（`aria-label` のみ等）なら可視テキストを添える ②関連する既存要素との並び（横並び・折り返し・縦位置の揃え）を決める ③文字サイズ・色を隣の要素の階層（主 / 補助）に揃える（ラベルの見えないスイッチをドロップダウンの下に置くだけだと、何のスイッチか分からず並びも崩れる）

## 実装ルール

- ユーザー入力を HTML として挿入しない（`dangerouslySetInnerHTML` / `innerHTML` は XSS になる）。整形が必要ならテキストとして描画するか、サニタイズ済みの markdown レンダラを通す
- 色・余白・フォントサイズは、repo にトークン（テーマ・CSS 変数）があればそれを使う。値を直書きすると、テーマ変更やダークモードで追随しない
- コンポーネントを別のコンポーネントの中で定義しない（毎回別の型として作り直され、再描画のたびに remount して state が消える）
- props や他の state から計算できる値は state に持たず、描画中に導出する。useEffect で state を同期させると 1 フレーム古い値が描画される
- useEffect で購読・タイマー・イベントリスナーを張ったら cleanup を返す
- 並び替え・挿入があるリストの key に配列の index を使わない（行の state が別の行に移る）
- API レスポンスは error / 空を扱ってから使う。生成された API 型がある repo では手書きの型を作らない
