# compact-claude-md — CLAUDE.md をルールを落とさずに縮める

CLAUDE.md（グローバルの `~/.claude/CLAUDE.md`、プロジェクトの `./CLAUDE.md`）は毎ターン読み込まれる。同じことの繰り返し・自明な例・長い前置きを削り、ルールそのものは 1 つも落とさずに縮める。

やるのは冗長な部分の除去で、要約ではない。要約はルールを落とす。

```
/compact-claude-md [path]
```

引数が無ければ `~/.claude/CLAUDE.md` と、カレントに `CLAUDE.md` があればそれを候補として番号付きで出し、選んでもらう。

## 1. 落とさないもの・落として良いもの

落とした時点でデグレになるもの:

| 種類 | 例 |
|---|---|
| 具体的な禁止事項 | 「〜しない」「〜は使わない」 |
| 固有情報 | コマンド・ツール名・パス・パッケージ名 |
| 判断の閾値 | 「1時間未満は会話内で」「200行以内」 |
| 過去の指摘に由来する理由 | 日付・PR 番号つきの経緯。「次からは〜」で足されたルールはその理由ごと残す |
| ユーザーが明示した好み | 番号付きリスト、日本語で応答 等 |
| セキュリティのルールすべて | supply chain / secrets / prompt injection。章ごとそのまま残す。迷ったら残す |
| 手順の順序と各ステップの核 | 「暗黙のワークフロー」のような番号付きステップ、`/reflect` などの独自ワークフローの定義。行は削っても順序と核は残す |
| `@path` の import 行 | 1 文字も変えない。import 先のファイルは対象外 |

落として良いもの:

- 同じ内容を別の言葉で繰り返している段落
- 本文の言い換えになっている例（「〜しない。例: 〜しない」）。自明な例の列挙は代表 1〜2 個に絞る
- 本文で伝わっている見出しの説明文
- 長い根拠説明。判断に必要な核だけ 1 行に縮める
- 1〜2 行しか無い `####` 以下の見出し。箇条書きに畳む

## 2. 現状を測る

1. 対象が symlink なら実体のパスを調べる（`ls -l`）。以降の Read / Edit は実体に対して行う（symlink 経由の Edit は拒否されることがある）
2. 全文を Read する
3. `wc -lc` で行数とバイト数を測って報告する。token 数はここでは測れないので、実数はユーザーに `/context` で見てもらう
4. 他のファイルから引かれている見出しを洗う。skill や agent が「CLAUDE.md の「〜」」と見出し名で参照していることがある。対象が `~/.claude/CLAUDE.md` なら、`~/.claude/skills/` `~/.claude/agents/` `~/.claude/commands/` と、入れている plugin（`~/.claude/plugins/cache/`）を見出し名で grep する。引かれている見出しは名前を変えない
5. ファイル内の参照も洗う。「下記「〜」に従う」「同 PR で」のように前後の位置に依存する書き方は、並べ替えると意味が切れる

## 3. 削減候補を挙げる（まだ書き換えない）

- 同じ趣旨のルールが別の章に重複している箇所を、行番号のペアで挙げる。片方を残し、もう片方は残した側への参照にする
- 5 項目以上の箇条書きで、3 項目以上が同じカテゴリなら 1 項目にまとめられないかを見る
- コード例が 3 つ以上あり、最初の 1〜2 個で伝わるなら後ろを削る
- 見出しと本文 1 文だけの節は 1 行に畳む

候補ごとに、1 の表のどれにも当たらないことを確かめる。当たるものは候補から外し、「意図して残した箇所」として 4 で示す。

## 4. 案を見せて合意を取る

書き換える前に必ず見せる。合意なしに書き換えない。

1. 変更点を番号付きで出す。それぞれ「どこを・どうする・何行減るか」を書く（例: `1. Security の重複説明を統合（-20 行）`）
2. 前後の行数とバイト数の見込みを出す
3. 意図して残した箇所を挙げる
4. 修正の指示があれば反映して出し直す

1 回で 30〜40% 減れば良い方。50% を超える案はルールを落としている可能性が高いので、1 の表と照らして見直す。プロジェクトの CLAUDE.md はグローバルより詰まっていることが多く、減る量は少なめに見積もる。

## 5. 書き換える

1. 戻せる状態にする。git で管理されていて未 commit の差分が無ければ、そのまま進める（`git checkout -- <path>` で戻せる）。それ以外は先に退避する

   ```bash
   cp <path> <path>.bak.$(date +%Y%m%d-%H%M%S)
   ```

2. 1 回の Write で全体を書く。常時読み込まれるファイルなので、半分だけ書き換えた状態を残さない
3. 残したルールの行は文言を変えない。動かすだけの行を書き直すと、次の突き合わせで落としたルールと区別できなくなる

## 6. 落としたルールが無いかを突き合わせる

読み直して「変わっていない」と判断するだけでは足りない。元の各行が新しいファイルにあるかを機械的に確かめる。

```bash
git show HEAD:<path> | grep -v '^$' | while IFS= read -r l; do
  grep -qxF -- "$l" <path> || printf '%s\n' "$l"
done
```

git 管理でなければ `git show HEAD:<path>` を退避したファイルの `cat` に置き換える。

- 出てきた行が「元にあって新しい側に無い行」。1 行ずつ、4 で合意した変更のどれに当たるかを説明できることを確かめる。説明できない行は落としたルールなので戻す
- 2 で洗った見出し名と、ファイル内の参照が切れていないかを見る

## 7. 報告

- 前後の行数・バイト数（`wc -lc` の実測）
- 変えた箇所の表（元の場所 / どうしたか）
- 戻し方（`git checkout -- <path>`、または退避ファイルのパス。退避ファイルは不要になったら消してもらう）
- `/context` で減った量を見てもらう
- 対象が symlink だった場合は、実体を編集したので symlink 側にも既に反映されていることを書く
- commit はしない

## 圧縮の型

見出しを箇条書きに畳む:

```markdown
## A

### A-1

短い説明

### A-2

短い説明
```

↓

```markdown
## A

- A-1 — 短い説明
- A-2 — 短い説明
```

理由をルールの行に入れる:

```markdown
- `--global` ではなくローカル設定を使う
- 理由: 他プロジェクトに影響を与えない
```

↓

```markdown
- `--global` ではなくローカル設定を使う（他プロジェクトに影響させない）
```

入れ子の列挙は 1 階層に畳み、代表例だけ具体的に残す。ただしセキュリティの章の列挙はそのまま残す。
